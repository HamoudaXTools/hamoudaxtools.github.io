# Hamouda XTools v14 — Connect Device

## الميزة
أضفنا قسم Connect Device في واجهة الموقع، بأزرار اكتشاف USB، واختيار منفذ Serial المتوافق، ثم قائمة "عايز تعمل إيه؟" (معلومات الجهاز، الملفات، تشخيص USB، فحص Firmware، النسخ الاحتياطي، إنهاء الاتصال).

## حقيقة دعم MTP في المتصفح
- MTP ليس واجهة عامة مدعومة في كل المتصفحات، وWebUSB لا يضمن الوصول إلى أجهزة MTP.
- الموقع لا يستطيع بمفرده قراءة موديل الهاتف أو Android build أو تنفيذ التفليش عبر MTP.
- زر USB يستخدم WebUSB حيث يدعمه المتصفح، ويعرض معلومات USB المتاحة فقط بعد موافقة المستخدم.
- لقراءة معلومات Android عبر ADB يجب تثبيت/تشغيل Windows Bridge وتفعيل USB debugging وموافقة المستخدم. هذا لا يحدث عبر MTP وحده.
- التفليش الحقيقي يحتاج أدوات الشركة وتعريفات وصلاحيات وبروتوكولات مناسبة لكل جهاز؛ هذه النسخة لا تنفذ عمليات كتابة أو مسح.

## الملفات
- `index.html`: الموقع الحالي مع قسم Connect Device.
- `hamouda.png`: صورة الموقع الأصلية المرفقة.
- `device-connect.js`: منطق اكتشاف USB وعرض إجراءات الجهاز.
- `windows-bridge/bridge.py`: نموذج أولي محلي لعرض أجهزة ADB، للقراءة فقط.
- ملفات Firebase الأصلية الموجودة في المشروع محفوظة كما هي.

## الاختبار
1. ارفع ملفات الموقع على HTTPS (مثل GitHub Pages).
2. استخدم Chrome/Edge حديثًا على Windows.
3. افتح قفل الهاتف واختر MTP، ثم جرّب "اكتشاف جهاز USB". قد لا يظهر الهاتف لأن MTP لا يعني دعم WebUSB.
4. لتجربة ADB، ثبّت Platform Tools، فعّل USB debugging ووافق على RSA، ثم شغّل Bridge محليًا.
5. اختبر على هاتف غير مهم أولًا. لم يتم نشر التعديل على موقعك الحي من هذه الحزمة.

## ما يلزم للتطوير الكامل
- تطبيق Windows Bridge موقّع ومثبت على جهاز الفني.
- دعم ADB رسميًا وموافقة USB debugging لقراءة معلومات Android.
- دعم خاص لكل شركة إذا احتجنا Download Mode/EDL/BROM أو التفليش.
- لا توجد مفاتيح سرية مضمّنة. لا تغيّر Firebase configuration إلا إذا كانت ملفات المشروع تتطلب ذلك.
